wheeltec_inventory_system 操作手册（V3：Nav2巡航路线搜索 + entry_side自动切换）
========================================================================

适用环境
--------
- Ubuntu 22.04 + ROS2 Humble
- 工作区：`~/wheeltec_ros2`
- 功能包：`wheeltec_inventory_system`
- 本版流程：
  - 根据目标货柜号读取 `route_waypoints.yaml`
  - 选择对应侧巡航路线和 `entry_side`
  - `NAV_ROUTE` 阶段调用 Nav2 `NavigateToPose` 逐点巡航
  - 巡航过程中数字识别持续工作
  - 目标编号稳定识别后取消 Nav2 并停车
  - 跟踪稳定后根据 `warehouse_layout.yaml` 判断目标间隙在前方/后方
  - `SEARCH_GAP` 按规划方向低速前进/后退，同时按 `entry_side` 检测间隙
  - 检测到候选间隙后进入 `WAITING_GAP` 静态确认宽度、稳定性和安全距离
  - 找缝超时或确认失败后，按原固定回退和调整序列 fallback 重试
  - 满足条件后按 `entry_side` 和入缝角速度倍率进入入缝

6. 摄像头与识别调试（T4）
------------------------
先开原始图像：
```bash
source /opt/ros/humble/setup.bash
source ~/wheeltec_ros2/install/setup.bash
ros2 run image_tools showimage --ros-args -r image:=/camera/color/image_raw
```

再开识别调试图：
```bash
ros2 run image_tools showimage --ros-args -r image:=/inventory/visualization
ros2 run image_tools showimage --ros-args -r image:=/inventory/debug_a4_region
ros2 run image_tools showimage --ros-args -r image:=/inventory/debug_digits
```

识别分割调试图含义：
- `/inventory/debug_a4_region`：观察 A4 是否被稳定框住，数字是否落在矫正后的 A4 内部。
- `/inventory/debug_digits` 左侧为二值图，中间为候选框过滤过程，右侧为最终 crop 和 union fallback。
- `raw candidates` 中橙色表示通过基础候选，红色表示尺寸/面积/比例不合格，蓝色表示竖线或横线噪声，紫色表示填充率异常，粉色表示贴近 A4 边缘。
- `filtered + rejects` 中绿色表示保留候选，粉色表示边缘候选，蓝色表示线条候选，紫色表示填充率候选，红色表示相对大小过滤候选。
- `final + union` 中绿色是最终数字框，青黄色 `union` 是 fallback 合并框，橙色 `relaxed` 是放宽救回的候选，黄色竖线 `split` 表示 union split 实际发生。
- 如果图上出现 `split reject: ...`，说明 union 没有满足双数字切分条件；单个 6 正常情况下应多见 `not_wide_enough` 或 `no_clear_valley`。

识别节点会低频输出分割统计：
- `raw`：原始轮廓数量。
- `area_ok`：面积过滤后数量。
- `shape_ok`：宽高和长宽比过滤后数量。
- `edge_ok`：填充率、线条噪声和 A4 边缘过滤后数量。
- `rel_ok`：相对最大候选面积/高度过滤后数量。
- `final`：最终用于分类的 digit candidates 数量。
- `rej(edge/line/extent)`：被边缘、线条、填充率过滤掉的数量。
- `union`：本次最终结果是否来自 union fallback。
- `SEG_DEBUG`：final=0 时输出 warped A4 尺寸、各层计数和 shape_ok 中得分最高候选。
- `SEG_CAND[n]`：逐个候选输出 `x/y/w/h/area/ar/ext/cx/cy/score/reason`，可直接判断被 `area_small`、`width_large`、`edge_left`、`relative_to_largest` 等哪一层过滤。

识别结果查看：
```bash
ros2 topic echo /inventory/recognized_number
```

重点看字段：
- `number`
- `confidence`
- `valid`
- `horizontal_offset`
- `estimated_distance`

如果 `showimage` 缺失：
```bash
sudo apt update
sudo apt install ros-humble-image-tools
```

识别参数现场调试顺序建议：
1. 先确认 A4 检测稳定，再看 `SEG_DEBUG warped=宽x高` 是否合理。
2. 近距离大数字被拒绝时，先看 `SEG_CAND` reason 是否为 `area_large`、`width_large`、`height_large` 或 `edge_*`，再放宽 `max_digit_*_ratio`、`a4_border_margin_*`。
3. 如果 final=0 但 shape_ok>0，确认 `enable_relaxed_digit_fallback=true`，必要时降低 `relaxed_fallback_min_score`。
4. 如果远距离数字被切碎，先适当增大 `morph_close_kernel_size`、`merge_gap_px`、`merge_gap_ratio`，再降低 `merge_min_y_overlap_ratio` 或增大 `merge_max_height_diff_ratio`。
5. 如果碎片噪声太多，再提高 `min_digit_area`、`min_digit_area_ratio`、`min_candidate_extent` 或 `min_area_ratio_to_largest`。
6. 如果最终绿色框包含太多空白或边框，减小 `crop_padding_px` 和 `union_fallback_padding_px`。
7. 如果单个 6 被 split 成两半，提高 `union_split_min_width_height_ratio` 或降低 `union_split_min_valley_ratio`；如果双数字无法 split，反向调整。

识别参数只维护在：
```bash
~/wheeltec_ros2/src/wheeltec_inventory_system/config/inventory_system.yaml
```

修改 YAML 后需要重新启动 `number_recognizer_node`。单独启动识别节点和启动完整盘库系统都会加载这份 YAML。

确认参数是否生效：

7. 路线配置检查（T5，任务启动前必做）
-----------------------------------
路线文件：
```bash
less ~/wheeltec_ros2/src/wheeltec_inventory_system/config/route_waypoints.yaml
```

重点检查：
- `routes.<route_name>.waypoints` 是巡航路线点，不是货柜精确坐标。
- `waypoints` 使用 `map` 坐标系，必须由建图后在 RViz 中标定。
- `cabinet_side_map` 中目标货柜号必须能找到 `left/right`。
- `side_route_map` 中 `left/right` 必须能找到对应路线名。
- 路线名必须真实存在于 `routes` 下。
- 调试前不要让路线点仍全部是 `{x: 0.0, y: 0.0, yaw: 0.0}`。

快速检查是否还有占位坐标：
```bash
grep -n "{x: 0.0, y: 0.0, yaw: 0.0}" \
  ~/wheeltec_ros2/src/wheeltec_inventory_system/config/route_waypoints.yaml
```

如果 grep 有输出，说明还未完成路线标定。可以做软件连通测试，但不要直接实车自动巡航。

9. mock识别测试：验证识别后取消Nav2（T3）
---------------------------------------
用途：在不依赖真实相机识别稳定性的情况下，验证 `NAV_ROUTE -> TARGET_TRACKING`。

先启动任务，让状态进入 `NAV_ROUTE`：
```bash
ros2 service call /inventory/start_mission wheeltec_inventory_system/srv/StartMission "{targets: ['2-3-1-2'], return_home: false}"
```

目标货柜号取自示例 `2-3-1-2` 的第二段，即 `3`。连续发布目标识别结果：
```bash
ros2 topic pub --rate 10 /inventory/recognized_number wheeltec_inventory_system/msg/RecognizedNumber "{number: '3', confidence: 0.95, valid: true, horizontal_offset: 0.0, attempts: 1, estimated_distance: 1.0}"
```

预期：
- mission log 出现“目标货柜识别稳定”。
- 当前 Nav2 巡航目标被取消。
- 小车连续短时间发布零速度停车。
- `/inventory/mission_state` 从 `NAV_ROUTE` 变为 `TARGET_TRACKING`。

如果只发 1 帧就停车，说明稳定判定参数过低；如果一直不停车，检查：
```bash
ros2 param get /mission_manager_node target_recognition_stable_frames
ros2 param get /mission_manager_node target_recognition_stable_time_sec
ros2 topic echo /inventory/recognized_number
```

11. 入缝方向参数测试（低速、空旷区域）
------------------------------------
当前 `ENTERING_GAP` 已拆成 3 个子阶段：
- `ENTERING_TURN`：只在这里使用较大的转向角速度切入缝隙。
- `ENTERING_STRAIGHT_ALIGN`：转向完成后停车/记录直行起点。
- `MOVING_TO_GRID_CENTER`：沿目标缝隙航向直行到目标深度格中心，只允许很小的 yaw hold。

查看参数：
```bash
ros2 param get /mission_manager_node entry_turn_yaw_delta_rad
ros2 param get /mission_manager_node entry_align_yaw_tolerance_rad
ros2 param get /mission_manager_node entry_turn_linear_speed
ros2 param get /mission_manager_node entry_turn_angular_speed
ros2 param get /mission_manager_node entry_straight_speed
ros2 param get /mission_manager_node entry_straight_yaw_kp
ros2 param get /mission_manager_node entry_straight_max_angular_speed
ros2 param get /mission_manager_node entry_side_hold_target_distance_m
ros2 param get /mission_manager_node entry_side_hold_kp
ros2 param get /mission_manager_node entry_side_hold_min_valid_points
```

调试原则：
- `entry_side=left` 时，`ENTERING_TURN` 的 `angular.z` 应为正。
- `entry_side=right` 时，`ENTERING_TURN` 的 `angular.z` 应为负。
- 进入 `MOVING_TO_GRID_CENTER` 后，不能再持续使用入缝转向角速度。
- 目标侧距离保持只在 `MOVING_TO_GRID_CENTER` 启用，`ENTERING_TURN` 不做侧距保持。
- 阿克曼底盘严禁按原地旋转思路调试。

直行阶段建议：
- `entry_straight_max_angular_speed` 先放在 0.08~0.15 rad/s。
- 如果已经平行但左右抖动，降低 `entry_straight_yaw_kp` 或增大 `entry_straight_yaw_deadband_rad`。
- 如果直行慢慢偏航，略增大 `entry_straight_yaw_kp`，但不要把 `entry_straight_max_angular_speed` 调得很大。
- 如果侧距保持导致左右修正过猛，先降低 `entry_side_hold_kp`，不要放大 `entry_straight_max_angular_speed`。

目标侧距离保持：
- `mission_manager` 根据路线配置解析目标货柜在 `left/right`，并发布 `/inventory/entry_side`。
- `target_side=left` 时，`MOVING_TO_GRID_CENTER` 使用左侧 +90° 附近雷达扇区，控制 `left_side_dist -> entry_side_hold_target_distance_m`，默认约 0.6m。
- `target_side=right` 时，`MOVING_TO_GRID_CENTER` 使用右侧 -90° 附近雷达扇区，控制 `right_side_dist -> entry_side_hold_target_distance_m`，默认约 0.6m。
- 0.6m 是入缝后与目标侧货柜保持的工作间距，避免贴柜刮碰，同时让车体沿目标货柜侧稳定直行到深度格中心。
- 侧距由 LaserScan 有效点 median 估计；过滤 nan、inf、超出 `range_min/range_max` 的点。目标侧有效点数不足时，本周期只用 yaw hold，并打印节流日志。
- 最终角速度由 `yaw_hold_cmd + side_distance_cmd` 合成，再经过 `entry_straight_max_angular_speed` 直行阶段限幅；`BLOCKED_LEFT_SIDE` / `BLOCKED_RIGHT_SIDE` 安全停车仍然优先。
- 日志 `entering_gap` 中重点看：`target_side`、`left_side_dist`、`right_side_dist`、`control_side_dist`、`side_error`、`yaw_hold_cmd`、`side_distance_cmd`、`final_angular_cmd`、`traveled`、`target_straight_distance`、`speed_scale`、`safety_reason`。

控制符号：
```text
target_side=left:
  side_error = left_side_dist - entry_side_hold_target_distance_m
  side_distance_cmd = entry_side_hold_kp * side_error

target_side=right:
  side_error = right_side_dist - entry_side_hold_target_distance_m
  side_distance_cmd = -entry_side_hold_kp * side_error
```

雷达左右方向检查：
- 在 RViz 或 `/scan` 中确认 `base_link` 左侧是否对应 +90°，右侧是否对应 -90°。
- 让车辆静止靠近左侧货柜，`left_side_dist` 应明显小于 `right_side_dist`；靠近右侧货柜时相反。
- 如果 gap 检测方向反了，调整 `gap_detector_node` 的 `left/right_gap_sector_*`。
- 如果只有入缝后侧距保持方向反了，优先调整 `mission_manager_node` 的 `enter_left_side_sector_*` / `enter_right_side_sector_*`，不要破坏已经调好的 gap detection。


12. 深度格中心入缝距离（本版关键）
--------------------------------
目标格式建议使用：
```bash
仓库号-货柜号-层号-depth_index
```
例如 `2-3-1-2` 表示目标货柜号为 3，层号为 1，深度格为 2。

动态入缝默认开启：
```bash
ros2 param get /mission_manager_node enable_grid_center_entry
ros2 param get /mission_manager_node grid_depth_m
ros2 param get /mission_manager_node entry_center_offset_m
```

计算方法：
```text
target_depth_center_m = (target_depth_index - 0.5) * grid_depth_m
target_straight_distance = target_depth_center_m + entry_center_offset_m
```

默认 `grid_depth_m = 2.4m`，不含 offset 时：
- `depth_index=1`：中心 1.2m
- `depth_index=2`：中心 3.6m
- `depth_index=3`：中心 6.0m
- `depth_index=4`：中心 8.4m

左右侧最大深度不同：
- left / 上侧 / 1-18 货柜：最大 `depth_index=4`
- right / 下侧 / 19-36 货柜：最大 `depth_index=3`

如果 `depth_index` 越界，`mission_manager` 会拒绝任务或进入 `ERROR`，不会继续盲目前进。
如果任务没有传入 `depth_index`，默认按 `depth_index=1` 执行，并打印 WARN。

`entry_center_offset_m` 标定方法：
1. 先设为 `0.0`，选择已知 depth_index 的货柜低速测试。
2. 如果停车太浅，例如差 0.20m 到中心，则把 `entry_center_offset_m` 增加 `+0.20`。
3. 如果停车太深，例如越过中心 0.15m，则把 `entry_center_offset_m` 减小 `-0.15`。
4. 每次只改小量，重复验证 depth_index=1 和最深格，确认误差一致。

为什么不能在整个 `ENTERING_GAP` 持续打方向：
- 车辆完成转入后，车体已经基本与两侧货柜平行。
- 此时继续使用大的固定 `angular.z` 会持续积累航向误差，导致越走越偏。
- 所以大转向只允许在 `ENTERING_TURN`，直行阶段只允许小角速度 yaw hold 或 `angular.z=0`。

`entry_align_yaw_tolerance_rad` 调法：
- 初值 0.08 rad，约 4.6 度。
- 转到一半就开始直行：减小该值。
- 已经平行但迟迟不直行：增大该值。

`entry_straight_yaw_kp` 与 `entry_straight_max_angular_speed` 调法：
- 直行阶段慢慢偏航：略增大 `entry_straight_yaw_kp`。
- 直行阶段左右抖动：降低 `entry_straight_yaw_kp`，或增大 `entry_straight_yaw_deadband_rad`。
- 直行阶段仍像在大幅打方向：降低 `entry_straight_max_angular_speed`，建议保持 0.08~0.15 rad/s。


13. WAITING_GAP 子阶段说明（本版关键）
-----------------------------------
`WAITING_GAP` 内部会按以下子阶段执行：
- `RETREATING`：SEARCH_GAP 超时后的 fallback 固定回退（默认 0.1m）
- `STOP_BEFORE_DETECT`：停车稳定
- `DETECTING_GAP`：连续缝隙检测
- `POSE_ADJUSTING`：检测失败后按偏移序列调整位姿

默认调整序列参数：
```yaml
gap_adjust_sequence: [-0.10, 0.10, -0.20]
```
含义：
- 负数：后退
- 正数：前进
- 每个偏移都相对“当前位姿”执行


14. gap_status 字段解释（T3）
---------------------------
```bash
ros2 topic echo /inventory/gap_status
```

核心字段：
- `gap_detected`：连续稳定帧达标后置 true
- `entry_width_ok`：估计缝宽是否达到 `required_entry_width`
- `front_left_safe`：左前安全扇区距离是否安全
- `allow_enter`：是否允许入缝（综合判定）
- `gap_width`：估计缝宽（m）
- `side`：检测成功时输出当前侧，未检测到时为 `none`
- `active_side`：当前正在检测的方向，来自 `/inventory/entry_side`
- `stable_frame_count`：当前连续稳定帧计数
- `failed_cycle_count`：检测周期失败计数
- `open_ratio`：主检测扇区开口点比例
- `max_open_run`：最长连续开口点数
- `open_window_start_deg / open_window_end_deg`：最佳开口窗口角度边界
- `min_front_left_dist`：左前安全扇区最小距离
- `current_adjust_index / current_adjust_offset`：当前位姿调整进度

19. 常见问题排查
---------------
1) `Unknown topic /scan` 或 `/camera/color/image_raw`
- 底层未启动，先检查 T1。

2) 编译提示找不到 `yaml-cpp`
- 安装 `libyaml-cpp-dev`。
- 重新 `colcon build --packages-select wheeltec_inventory_system`。

3) 启动任务后提示路线配置文件不存在
- 查 `/mission_manager_node route_waypoints_file`。
- 默认应为 `config/route_waypoints.yaml`。
- 确认已重新编译并 `source install/setup.bash`。

4) `NAV_ROUTE` 不动，日志提示 Nav2 action server 不可用
- 查：
  ```bash
  ros2 action list | grep navigate_to_pose
  ros2 action info /navigate_to_pose
  ```
- Nav2 未启动或 action 名称不一致时，先修外部导航启动。

5) `waypoints` 仍为 0.0
- 只能做软件连通测试。
- 不要实车自动巡航。
- 使用 Cartographer 建图后，在 RViz 的 `map` 坐标系下重新标定路线点。

6) TF 不连通
- 查：
  ```bash
  ros2 run tf2_ros tf2_echo map base_link
  ros2 run tf2_ros tf2_echo base_link laser
  ```
- `NAV_ROUTE` 依赖 Nav2 的 map 定位。
- `gap_detector` 依赖雷达点能转换到 `base_link`。

7) `recognized_number` 有结果，但一直不取消 Nav2
- 确认识别到的是目标货柜号，不是目标字符串的其他字段。
- 示例 `2-3-1-2` 的目标货柜号是 `3`。
- 检查稳定判定：
  ```bash
  ros2 param get /mission_manager_node target_recognition_stable_frames
  ros2 param get /mission_manager_node target_recognition_stable_time_sec
  ```
- 单帧误识别不会触发停车，这是正常设计。

8) `gap_width` 一直偏小或为 0
- 先看 `/inventory/gap_status.active_side` 是否正确。
- 再看对应侧扇区是否覆盖货柜侧：
  - left：`left_gap_sector_start_deg/end_deg`
  - right：`right_gap_sector_start_deg/end_deg`
- 再看 `open_point_min_distance` 是否过大。
- 用 RViz 叠加 `/scan` 验证开口几何。

9) 一直不进入 `ENTERING_GAP`
- 看 `/inventory/gap_status` 的 `allow_enter` 是否为 true。
- 若 `gap_detected=true` 但 `allow_enter=false`，优先查：
  - `entry_width_ok`
  - `front_left_safe`
  - `left_side_safe`

10) `/inventory/entry_side` 正确，但左右检测像是反了
- 先确认雷达坐标系在 `base_link` 下的正负方向。
- 调整 gap_detector 的左右扇区参数，不要改代码。
- 用 `ros2 topic echo /inventory/gap_status` 看 `active_side` 和窗口角度。

11) 入缝方向反了或没有朝目标侧转入
- `entry_side=left` 时 `angular.z` 必须为正，`entry_side=right` 时必须为负。
- 先确认 `/inventory/entry_side` 是否等于目标货柜解析出的 side。
- 再确认 `route_waypoints.yaml` 的 `cabinet_side_map` 和雷达/底盘坐标方向。
- 本版不要再靠旧的 `enter_left_angular_multiplier` / `enter_right_angular_multiplier` 修正新入缝逻辑。

12) 入缝太浅
- 先确认任务传入了正确的 `depth_index`。
- 如果所有 depth 都偏浅，把 `entry_center_offset_m` 增大。
- 如果只有深格偏浅，检查里程计累计、地面打滑和 `max_dynamic_entry_distance_m` 是否过低。

13) 入缝太深
- 如果所有 depth 都偏深，把 `entry_center_offset_m` 减小。
- 如果只在直行末端明显越过，降低 `entry_straight_speed` 并确认 odom 没有延迟。

14) 入缝后仍持续转向
- 看日志中的 `phase`，正常应从 `ENTERING_TURN` 切到 `MOVING_TO_GRID_CENTER`。
- 如果已经在 `MOVING_TO_GRID_CENTER` 仍大幅转向，降低 `entry_straight_max_angular_speed`。
- 如果一直停在 `ENTERING_TURN`，检查 `entry_turn_yaw_delta_rad` 和 odom yaw 是否正确。

15) 转到一半就直行
- `entry_align_yaw_tolerance_rad` 太大，适当减小。
- 也检查 `entry_turn_yaw_delta_rad` 是否小于实际需要的转角。

16) 已经平行但 yaw hold 抖动
- 降低 `entry_straight_yaw_kp`。
- 增大 `entry_straight_yaw_deadband_rad`。
- 降低 `entry_straight_max_angular_speed` 到 0.08~0.10 rad/s。

17) 目标在左侧却继续向左贴近
- 看 `entering_gap` 日志：`target_side` 应为 `left`，`side_error` 小于 0 时 `side_distance_cmd` 应小于 0。
- 如果符号正确但实车仍向左，检查底盘 `angular.z` 正负方向或雷达左右扇区是否反了。
- 如果 `left_side_dist` 明显不可信，检查 `enter_left_side_sector_start_deg/end_deg` 和雷达 TF。

18) 目标在右侧却继续向右贴近
- 看 `target_side` 是否为 `right`，`side_error` 小于 0 时 `side_distance_cmd` 应大于 0。
- 如果符号正确但实车仍向右，检查底盘 `angular.z` 正负方向或雷达左右扇区是否反了。
- 如果 `right_side_dist` 明显不可信，检查 `enter_right_side_sector_start_deg/end_deg` 和雷达 TF。

19) side distance hold 抖动
- 降低 `entry_side_hold_kp`。
- 保持 `entry_straight_max_angular_speed` 在 0.08~0.10 rad/s。
- 检查侧向扇区是否扫到货柜边角、立柱或空洞；必要时略收窄对应 `enter_*_side_sector_*`。

20) 雷达点数不足
- 日志会出现 `side_hold_status=INSUFFICIENT_LEFT_POINTS` 或 `INSUFFICIENT_RIGHT_POINTS`。
- 检查 `/scan` 是否新鲜、雷达 `range_min/range_max`、目标侧扇区角度和货柜是否进入 ±90° 附近视野。
- 点数不足时系统只用 yaw hold，不会沿用旧侧距盲目控制。

21) `BLOCKED_LEFT_SIDE` / `BLOCKED_RIGHT_SIDE` 仍然触发
- 这是安全停车逻辑，优先级高于目标侧距离保持。
- 先看 `side_dist` 是否低于 `enter_stop_distance`，再看 `enter_slow_distance` 是否导致 `speed_scale` 降低。
- 不要为了走完 `target_straight_distance` 关闭或绕过侧向安全阻塞。

22) depth_index 越界
- left / 上侧 / 1-18 货柜只允许 1..4。
- right / 下侧 / 19-36 货柜只允许 1..3。
- 越界时任务会被拒绝或进入 `ERROR`，这是安全保护。

18) 没有传入 depth_index
- 直接传货柜号或只传到层号时，默认 `target_depth_index=1`。
- 日志会打印 WARN：未传入 depth_index，默认走第 1 深度格。

19) 返航不动
- 查 `/mission_manager_node` 是否在 `RETURNING`。
- 查 `navigate_to_pose` action 是否在线。
- 查里程计 `/odom_combined`、`/odom` 是否有发布者。
  ```bash
  ros2 param set /mission_manager_node enter_left_angular_multiplier -1.0
  ros2 param set /mission_manager_node enter_right_angular_multiplier 1.0
  ```
- 确认后写回 `inventory_system.yaml`。

12) 返航不动
- 查 `/mission_manager_node` 是否在 `RETURNING`。
- 查 `navigate_to_pose` action 是否在线。
- 查里程计 `/odom_combined`、`/odom` 是否有发布者。
